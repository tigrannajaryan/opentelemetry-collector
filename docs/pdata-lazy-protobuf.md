# Lazy protobuf for pdata

The pdata protobuf implementation generated by `internal/cmd/pdatagen` uses
lazy decoding and lazy encoding for generated message fields. The design is
inspired by Splunk's experimental LazyProto project:
https://github.com/splunk/exp-lazyproto.

The goal is to make passthrough workloads cheap. `UnmarshalProto` validates the
input bytes, keeps references to those bytes, and defers allocating and
populating generated structs until callers access fields. `MarshalProto` can
then copy unchanged wire bytes directly instead of re-encoding the full message
tree.

## Runtime state

Each generated pdata protobuf struct has a `lazy proto.LazyMessage` field. The
shared state holder is implemented in `pdata/internal/proto/lazy.go` and added
to generated structs by
`internal/cmd/pdatagen/internal/proto/templates/message.go.tmpl`.

`proto.LazyMessage` stores:

* `bytes`: the exact wire bytes for this message, or nil if the message must be
  encoded from fields.
* `parent`: the parent message's lazy state, used to invalidate ancestor wire
  bytes when a child changes.
* `decoded`: whether this message's direct fields have already been populated
  from `bytes`.

The generated message methods use that state as follows:

* `UnmarshalProto` calls `validate<Message>Proto`, resets the struct, and stores
  the original bytes with `lazy.Init`.
* `EnsureDecoded` decodes only the current message's direct fields. Embedded
  generated messages keep their own raw byte references.
* `MarkModified` clears this message's reusable wire bytes and walks up the
  parent chain so all ancestors reassemble their output.
* `DecodeAll` recursively materializes a message tree and clears lazy state. It
  is used where code needs ordinary in-memory struct semantics.

## Validation pass

Lazy decoding means `UnmarshalProto` cannot return decode errors later from
field getters. To preserve the existing error behavior, `UnmarshalProto`
performs a validation-only pass before retaining the input bytes.

The validation generator lives in
`internal/cmd/pdatagen/internal/proto/proto_validate.go`. It emits the same wire
type and bounds checks as the decoder, including recursive validation for
embedded generated messages. The pass discards all decoded values, so it does
not allocate pdata message trees.

Custom fixed-size ID messages such as trace IDs, span IDs, and profile IDs are
validated by helpers in `pdata/internal/lazy_proto.go` because those types use
hand-written protobuf support instead of generated lazy state.

## Lazy decoding

`internal/cmd/pdatagen/internal/proto/proto_unmarshal.go` now generates
`decodeProto` snippets instead of eager full-tree unmarshalling. Scalar, enum,
string, bytes, and oneof scalar fields are decoded into the current struct when
`EnsureDecoded` runs.

For generated message fields, `decodeProto` records the length-delimited
sub-slice on the child message:

* singular messages initialize the existing or newly allocated child.
* repeated message fields append a child and initialize its lazy state.
* oneof message values allocate the oneof wrapper, allocate the child, and
  initialize the child lazy state.

The child does not decode its fields until code accesses it through generated
public accessors or internal helpers. Getter templates in
`internal/cmd/pdatagen/internal/pdata/*field.go` call `EnsureDecoded` before
reading fields. Setter templates call `EnsureDecoded` and then `MarkModified`.

Some handwritten pdata surfaces also read internal fields directly. Those are
adapted explicitly:

* `pdata/pcommon/value.go` and `pdata/pcommon/map.go` ensure values are decoded
  before direct inspection.
* `pdata/internal/wrapper_*.go` ensures generated top-level data is decoded when
  converting to and from pdata wrapper types.
* `pdata/xpdata/request/context.go` fully materializes request context before
  decoding it into Go context values.

## Lazy encoding

Generated `SizeProto` and `MarshalProto` first check `lazy.HasBytes()`. If raw
bytes are still available, size is `len(bytes)` and marshal copies those bytes
directly. This preserves the original field order and unknown fields for
unchanged messages.

When bytes are nil, generated marshal code calls `EnsureDecoded` and encodes the
struct fields normally. Lazy encoding is per message, so a modified parent can
still copy raw bytes for unchanged child messages while reassembling the parent
payload.

Modification tracking is local to each message tree. There is no global state.
Generated setters and handwritten mutators call `MarkModified`; `MarkModified`
clears wire bytes on the current message and every ancestor through the stored
parent pointers.

Repeated slice access is conservative. The public slice getter marks the owning
message modified because the slice API can mutate elements after the getter
returns and does not provide a mutation callback back into the generated proto
message.

## Eager materialization boundaries

Most public pdata access should remain lazy. A few internal paths must fully
materialize before mutating generated structs directly:

* OTLP request `UnmarshalProto` methods in `pdata/*/*otlp/request.go` call
  `DecodeAll` before running deprecated-field migration helpers from
  `pdata/internal/otlp`.
* Raw gRPC server adapters in `pdata/*/*otlp/grpc.go` call `DecodeAll` before
  migration for the same reason.
* Tests that compare generated internal structs call `DecodeAll` before
  equality assertions because otherwise equivalent messages may differ only by
  lazy raw-byte state.

These boundaries avoid stale raw bytes being decoded after a migration or direct
internal mutation has already updated the materialized fields.

## Generated code ownership

The source of truth for generated lazy protobuf behavior is:

* `internal/cmd/pdatagen/internal/proto/templates/message.go.tmpl`
* `internal/cmd/pdatagen/internal/proto/proto_validate.go`
* `internal/cmd/pdatagen/internal/proto/proto_unmarshal.go`
* `internal/cmd/pdatagen/internal/proto/proto_decode_all.go`
* `internal/cmd/pdatagen/internal/pdata/*field.go`

The generated outputs are under `pdata/internal/generated_proto_*.go` and the
public pdata generated accessors under `pdata/pcommon`, `pdata/plog`,
`pdata/pmetric`, `pdata/ptrace`, and `pdata/pprofile`.

After changing generator behavior, run `make genpdata` from the repository root
and then verify with `go test ./...` from `pdata`. Nested pdata modules such as
`pdata/pprofile` and `pdata/xpdata` are covered by the root `make gotest`
target.
